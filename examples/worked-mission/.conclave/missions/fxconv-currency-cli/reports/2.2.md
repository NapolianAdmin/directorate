**1. CRITICAL — fetch_rate() sends no User-Agent, gets blocked by Cloudflare, and the resulting 403 is misreported as "invalid currency code." The tool is currently 100% non-functional against the live API for every currency pair, valid or not.**

Command:
```
python -m fxconv USD EUR 100
```
Output:
```
fxconv: error: invalid currency code (from='USD', to='EUR'): HTTP 403
```
Exit: 1

Root-cause verification — raw request with urllib's default UA:
```
$ python -c "
import urllib.request, urllib.error
url = 'https://api.frankfurter.app/latest?from=USD&to=EUR'
try:
    with urllib.request.urlopen(url, timeout=10) as r:
        print('STATUS', r.status); print(r.read())
except urllib.error.HTTPError as e:
    print('HTTPError', e.code, e.reason); print(e.read()[:500])
"
HTTPError 403 Forbidden
b'error code: 1010\n'
```
Same request with a browser User-Agent succeeds immediately:
```
STATUS 200
b'{"amount":1.0,"base":"USD","date":"2026-09-11","rates":{"EUR":0.86266}}'
```
"error code: 1010" is Cloudflare's bot/browser-integrity-check block, triggered specifically because `urllib.request.urlopen()` sends the default `Python-urllib/3.13` User-Agent and `fxconv/rates.py` never sets a custom one. Separately, `fetch_rate()` catches *any* `urllib.error.HTTPError` — regardless of status code — and unconditionally raises `InvalidCurrencyCode`. So a totally unrelated bot-block (403) gets relabeled as a bad currency code. Confirmed this also fires for `USD ZZZ` and `USD XXX`:
```
$ python -m fxconv USD ZZZ 100
fxconv: error: invalid currency code (from='USD', to='ZZZ'): HTTP 403
$ python -m fxconv USD XXX 100
fxconv: error: invalid currency code (from='USD', to='XXX'): HTTP 403
```
identical to the USD/EUR output — a real code and a fake code are indistinguishable to the user, and neither actually works. (With a proper UA, Frankfurter does correctly 404 an unknown code like ZZZ with `{"message":"not found"}` — so the intended logic is sound, it's just unreachable because the 403 fires first.)

LESSON CANDIDATE
Any CLI/library that wraps an external HTTP API with urllib and classifies errors by status code must (1) set an explicit User-Agent header, since several major API hosts silently 403-block the default UA, and (2) narrow HTTPError-to-domain-exception mapping to the specific status codes the API contract documents rather than catching HTTPError unconditionally.
