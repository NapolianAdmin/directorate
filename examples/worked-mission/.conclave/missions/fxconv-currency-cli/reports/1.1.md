RISKS AND UNKNOWNS
- `HTTPError.code` is used in the `InvalidCurrencyCode` message; if Frankfurter ever returns a non-404 status for other error types (e.g. 5xx) it would still be classified as `InvalidCurrencyCode` since any `HTTPError` is caught before `URLError`. This matches the stub's explicit instruction ("catch `urllib.error.HTTPError`... and raise this") and the documented API contract (non-200 = invalid code), so I did not special-case status codes.
- I added a `TypeError` catch alongside `JSONDecodeError`/`KeyError` (stub only lists the latter two) to guard against `json.loads` succeeding on a non-dict body (e.g. a bare JSON array/number) where `payload["rates"]` would raise `TypeError` instead of `KeyError`. This is a strict superset of the required behavior, not a deviation from it.
