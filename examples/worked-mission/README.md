# Worked example: fxconv currency CLI

A real `.conclave/` directory from an actual conclave mission — not a fabricated example.
Every command in every report was really run; every finding was really reproduced. This
directory is the mission's actual output, copied verbatim from the repo it ran in.

## What's real here

- `.conclave/missions/fxconv-currency-cli/MISSION.md` and `PLAN.md` — the real mission
  spec and the real wave plan, with real checkpoint commit SHAs (`bf20206`, `694a0cd`,
  `32493cd`, `4fbf470`).
- `.conclave/missions/fxconv-currency-cli/DECISIONS.md` — real, and empty. This mission
  didn't need a divergence wave (the architecture was unambiguous enough that no
  brainstorm-before-planning step was warranted) — an empty DECISIONS.md is a legitimate
  outcome, not an omission.
- `.conclave/missions/fxconv-currency-cli/reports/` — all nine real work-order reports,
  verbatim, plus a writeup of the one genuinely failed wave in this mission (which the
  Chief had to inject itself, since no real agent produced a failing report). Start with
  `1.2.md` — an implementer's refusal to comply with a disclosed sabotage instruction —
  it's the most interesting artifact in this example. Then `2.1.md`/`2.2.md` (Security
  Auditor and Red Team QA independently finding real bugs, including one that made the
  tool 100% non-functional against the live API), then `3.1.md`–`3.3.md` (the fixes,
  each independently re-verified live by the Chief), then `sabotage-experiment-wave.md`.
  `0.1.md` (the Architect's interface stubs) and `1.1.md`/`1.3.md` (the other two Wave 1
  implementers) round out the set.
- `.conclave/LESSONS.md`, `.conclave/STANDING-RULES.md`, `.conclave/ledger/lessons.jsonl`
  — the real ledger this mission produced: one lesson recorded live during the fxconv run
  itself (the rollback-granularity finding), plus three more recorded afterward when this
  skill's own development workflow hit the same class of problem it's meant to prevent —
  background dispatch silently breaking "the whole wave in one turn," a `reports/` promise
  with no paired instruction to fulfill it (found by building *this* directory), and a
  rate limit tripped by dispatching too many parallel review agents at once. All four
  generated by the real `conclave.py` CLI, not hand-written. `lesson digest` flagged the
  two `high`-severity ones as promotion candidates — both were, in fact, promoted, not
  into `STANDING-RULES.md` but directly into fixed instructions in `protocol.md` and
  `SKILL.md` (deeper than a standing rule: the mistake is no longer possible to make by
  following the docs, not just discouraged).

## What's not here

The actual `fxconv/` source code and `tests/` this mission built aren't included — this
directory is about the *conclave process artifacts*, not the deliverable code, and keeping
this example small means keeping it to what a Chief would actually commit alongside a real
project (`.conclave/`, per the skill's own advice: "commit `.conclave/` — the code can be
regenerated, the scar tissue can't").

The `sabotage-experiment` git branch this mission used to test rollback granularity was
never merged and isn't reproduced here as a branch — its exact commands and output are
written up instead in `reports/sabotage-experiment-wave.md`, since a real git branch
doesn't travel well as static files.
